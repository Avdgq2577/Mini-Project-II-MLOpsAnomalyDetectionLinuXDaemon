Here is the **complete, step-by-step guide to run a live demo** of your MLOps Real-Time Anomaly Detection Linux Daemon project.

---

### 🚀 Complete Live Demonstration Setup

#### Step 1: Register and Start the System Telemetry Service

Run these commands in your Konsole terminal to deploy the service into systemd:

```bash
sudo cp daemon/systemmonitor.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now systemmonitor.service
sudo systemctl status systemmonitor.service
```

---

#### Step 2: Start the MLflow UI Dashboard (Terminal 1)

Open **Terminal 1** and start the MLflow experiment tracking dashboard:

```bash
source proenv/bin/activate
mlflow server --backend-store-uri sqlite:///mlflow.db --default-artifact-root ./mlruns --host 0.0.0.0 --port 5000
```
> 📊 **Demo Link**: Open your browser at `http://localhost:5000` to show the MLflow dashboard tracking model parameters & metrics.

---

#### Step 3: Launch the FastAPI Anomaly Detection API (Terminal 2)

Open **Terminal 2** and start the model inference microservice:

```bash
source proenv/bin/activate
python -m uvicorn api.main:app --host 0.0.0.0 --port 8000
```
> ⚡ **Demo Link**: Open `http://localhost:8000/docs` in your browser to view the interactive FastAPI Swagger UI documentation.

---

#### Step 4: Run the Telemetry Collector Daemon (Terminal 3)

Open **Terminal 3** to run the telemetry daemon and stream live OS metrics (CPU, Memory, Disk, Network I/O) to the API:

```bash
source proenv/bin/activate
python daemon/telemetry_collector.py
```
*You will see live predictions logged every second:*
```text
2026-08-26 09:41:14 - TelemetryDaemon - INFO - Sent successfully. Prediction: Normal (Score: 0.12)
```

---

#### Step 5: Run Continuous Data Drift Monitor (Terminal 4)

Open **Terminal 4** to monitor statistical data drift (using Kolmogorov-Smirnov 2-sample tests) and trigger automated retraining if system behavior shifts:

```bash
source proenv/bin/activate
python mlops/drift_monitor.py
```

---
