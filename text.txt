Unified System Workflow & Component Integration
The proposed system operates through four tightly coupled layers that form a closed-loop monitoring and lifecycle pipeline:
1. Host-Level Telemetry Collection (systemd + psutil): A lightweight Python daemon runs natively on the Linux OS, managed by
a native systemd unit file to ensure auto-restart and strict memory limits. At sub-second intervals, the daemon utilizes psutil to
sample kernel and hardware metrics. It maintains a micro-batch buffer in RAM and transmits telemetry asynchronously to the
inference engine, ensuring zero dropped metrics even under elevated OS load.
2. Containerized Real-Time Inference (Docker + FastAPI): The telemetry payload is received by a Dockerized FastAPI
microservice. The service routes raw metric vectors through a prepackaged scikit-learn pipeline for standard feature
normalization before passing them to the trained Isolation Forest algorithm. By isolating the inference environment within Docker,
the host OS remains clean of complex machine learning dependencies. The endpoint returns a structured JSON payload
containing the binary classification (-1 for anomaly, 1 for normal) along with an anomaly score.
3. Asynchronous Experiment & Feature Logging (MLflow Tracking): Upon serving an inference request, the FastAPI service
asynchronously forwards the input features, calculated anomaly scores, and execution latencies to the MLflow tracking service.
This builds a continuous operational database of system behavior without adding latency to the main prediction path.
4. Continuous Monitoring & Retraining Loop (MLOps Pipeline): An automated MLflow background worker periodically evaluates
incoming operational data against historical training sets. If statistical tests indicate concept or data drift (e.g., following a kernel
upgrade or new application deployment), an automated pipeline executes to retrain the Isolation Forest model on the updated
telemetry distribution. The new model version is registered in the MLflow Model Registry, and the FastAPI service hot-reloads the
updated artifact dynamically without interrupting daemon communications.
